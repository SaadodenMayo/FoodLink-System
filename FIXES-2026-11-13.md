# FoodLink – Reliability and Login Experience Fixes (2026-11-13)

## Login experience
- Unauthenticated visits to `/` show an animated FoodLink intro before displaying two portal choices.
- Customer choice opens `/customer-login`; Admin / Owner / Rider choice opens `/portal-login`.
- Login forms animate into view and offer a return link to portal selection.

## Functional reliability fixes
- Client refresh now handles each API resource independently rather than failing the entire refresh when one request fails.
- Notifications are added to the same in-memory database object as the associated change and persisted together; this prevents a later write from overwriting notification records.
- Order status transitions are validated server-side for owner and rider roles.
- Riders may only accept Ready for Pickup orders in their assigned municipality, up to 10 active deliveries; only the assigned rider may confirm pickup and delivery, and delivery requires a proof image.
- Address map pins must be explicitly confirmed by clicking the map before saving.
- Dark theme preference is restored after reload; profile photo is displayed in account avatars.
